## 2. 판단순서

1. 사용자의 최신 명시 결정
2. 해당 의미를 소유한 위 표의 단일 정본
3. 승인된 활성 작업 패킷
4. 실행 명세·검증 증거
5. 코드·Git 이력·과거 문서

문서 번호가 앞선다는 이유로 다른 영역의 결정을 덮지 않는다. 서로 다른
소유문서가 같은 의미를 다르게 정의하면 임의 해석하지 않고 작업을 `BLOCK`한
뒤 소유 정본을 먼저 보정한다.

## 3. 읽기·배정 규칙

- 작업자는 7개 문서를 매번 전부 읽지 않는다.
- 활성 패킷은 02~05의 **최하위 절 또는 안정 anchor**, 필요한 06 결정 ID,
  matrix ID만 지정한다.
- `관련 문서 전체 참고`와 파일명만 적은 배정을 금지한다.
- 00은 정본 소유권이 불분명할 때, 01은 범위·Wave 경계를 판단할 때만 읽는다.
- LOW/MEDIUM 패킷의 정본 읽기량은 총 250줄, HIGH는 350줄 이내를 권장한다.
- 최하위 계약절은 20~60줄을 권장하고 80줄을 넘으면 새 문서를 만들기 전에
  기존 절을 세분화한다.

## 5. 개정 규칙

- 하나의 결정은 한 정본만 본문을 소유하고 다른 문서는 링크한다.
- 현재 branch·SHA·진행률·모델 가용성·후보 상태·테스트 수치를 정본에 넣지 않는다.
- 새 버전이 승인되면 현재 트리에는 최신 파일만 두고 이전 버전은 Git 이력으로
  보존한다.
- 새 정본은 위 7개 중 어느 문서도 의미상 소유할 수 없을 때만 검토한다.
- 분량이 늘었다는 이유만으로 문서를 합치거나 새 문서를 만들지 않는다.
