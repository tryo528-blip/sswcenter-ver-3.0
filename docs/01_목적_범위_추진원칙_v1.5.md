# SSWCenter v3.0-alpha 목적·범위·추진원칙 v1.5

> 기준일: 2026-07-28 KST

## 1. 프로젝트 목적

서울노인복지센터의 직원, 수급자, 인정, 계약, 배정, 일정, 실제근무, 업무,
파일, 수납과 출력 정보를 일관된 내부 업무체계로 연결하는 사내망 전용 ERP를
구축한다.

사용자는 오늘 처리할 업무와 예외를 먼저 보고, 처리할수록 미완료 업무와 경고가
줄어드는 흐름을 사용한다. 확정된 업무사실과 변경이력은 과거 시점 기준으로
재현할 수 있어야 한다.

## 2. Clean Rebuild 추진원칙

- 검증된 Wave 0 기반은 유지한다.
- Wave 1과 Wave 2는 이전 product code·migration·DTO·화면 컴포넌트를
  복사하지 않고 현재 정본에서 다시 구현한다.
- 기존 구현·테스트·문서는 회귀와 비교 증거로만 사용한다.
- 사용자에게 익숙한 화면구조·업무용어와 비충돌 업무의미는 보존한다.
- 최신 결정과 충돌하는 deprecated 호환필드는 만들지 않는다.
- DB·API·OpenAPI·생성 TypeScript 타입·UI·테스트를 같은 작업단위에서
  동기화한다.

이 저장소는 새 기준으로 시작하는 **SSWCenter v3.0-alpha 제품 저장소**다. 기존 v2.2 저장소,
branch, archive ref와 완료 SHA는 비교·회귀·복구 증거일 뿐 정본 계약이 아니다.
각 작업의 정확한 기준 SHA와 branch는 활성 작업 패킷과 검증 증거에 기록하며,
현재 진행상태·담당·SHA는 활성 패킷과 증거가 소유한다.
[06 개발로드맵](06_개발로드맵_결정현황_v1.2.md)은 개발순서·gate 시점·
결정 register만 소유한다.

## 3. 제품·운영 범위

- React + TypeScript + Vite 프론트엔드
- FastAPI + Python 백엔드
- PostgreSQL + Alembic
- Windows 단일 서버
- 센터 내부망의 데스크톱·노트북 브라우저

  도구는 재해복구용 외장 SSD에 보관

## 4. Wave 구현 경계

이 절이 프로젝트 범위와 Wave 경계의 단일 원문이다.

| 단계 | 포함 범위 | 명시적 경계 |
|---|---|---|
| Wave 0 | PostgreSQL 기반, 인증·PIN·세션·CSRF·권한·감사·개발/운영 안전장치, 기본 React shell, 직원·재직·직종·역할·번호카운터 기반 | 검증된 기준을 유지하며 같은 의미 모델을 중복 생성하지 않음 |
| Wave 1 Clean | 직원·민감정보·재직·직종·역할·자격증·서비스 제공자격·교육·검진·분기상담, 수급자·보호자·독립 납부자, 인정·등급·혜택·승인금액, 서비스계약·서명자, 인정 전환, 요양보호사·사회복지사·간호사 배정 | 사람·인정·계약·배정까지만 구현 |
| Wave 2 Clean | 공식 업무카드·개인 할 일, 급여계획서, 일정 원장, 확정월 잠금, 실제 급여제공 순서를 소비하는 직원교체 상담 | 실제근무 증거 수집모델은 만들지 않고 Wave 3의 안정 인터페이스를 소비하도록 설계 |
| Wave 3 | 공단 일정 원본, RFID 원본·매칭, 실제근무·실제 급여제공 증거, 일정정정 | 외부 원본과 실행사실 소유 |
| Wave 4 | 수가·월한도·본인부담금·청구·수납·은행매칭 | 공식 규칙과 금액계산 소유 |
| Wave 5 | 파일함 구현, OCR, 공식 출력, 연차·기타휴가, 복구 완성 | 파일·문서·출력 실행모델 소유 |

각 Wave의 상세 업무규칙은 해당 영역 정본에 둔다. 이 절에는 같은 규칙 본문을
복사하지 않는다.

## 5. 교차 Wave 원칙

- 앞 Wave는 후속 Wave가 참조할 업무개념을 `IDENTITY`·`PERIOD_FACT`·
  `REVISION`·`CURRENT_PROJECTION` 의미로 분류한다. 실제 Wave 1 테이블·PK·FK
  매핑은 04만 소유한다.
- `IDENTITY`는 정정 뒤에도 같은 업무대상을 뜻하는 뿌리다.
- `PERIOD_FACT`는 적용기간을 가진 사실이다. 정정은 기존 사실을 침묵 변경하지
  않고 무효화·대체 관계와 새 사실 ID를 남긴다.
- `REVISION`은 같은 업무대상의 버전이며, 실제 revision 구조가 승인된 영역에서만
  사용한다. 단순 기간행을 임의로 revision이라 부르지 않는다.
- `CURRENT_PROJECTION`은 원장에서 계산한 현재값이다. 별도 승인 없이 후속
  이력의 FK 대상이나 정본 identity로 사용하지 않는다.
- 각 개념은 정정 뒤 identity 지속 여부, 무효화·대체 방식과 후속 Wave가
  참조할 대상을 함께 기록한다.
- 후속 실행테이블이나 파일테이블을 참조하는 nullable 미래 FK는 미리 만들지
  않는다.
- 각 Wave는 직전 PASS SHA 위에 새 migration으로 추가한다.
- 한 Wave의 화면이나 trigger가 후속 Wave의 업무카드·상태·실행행을
  부수효과로 생성하지 않는다.
- 실제 개인정보·운영 DB·운영 파일을 개발·테스트에 사용하지 않는다.

## 6. 프로젝트 공통 제외

- 공단 청구자료 자동 제출과 공단 시스템 자동 업로드
- 외부 인터넷에서 ERP 접속
- 공유기 포트포워딩과 공인망 공개
- 모바일·태블릿 전용 구현·검증
- 반복일정/RRULE, 일정 자동추천, 지난달 일정 자동복사
- 3인 이상 방문일정
- 다중센터 운영

필요성이 생기면 기존 Wave 범위를 조용히 넓히지 않고 06 결정 현황 register에서
필요시점과 승인상태를 먼저 관리한다.
