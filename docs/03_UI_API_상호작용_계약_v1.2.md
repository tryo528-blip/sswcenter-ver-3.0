## 0. 적용 경계

기존 화면은 레이아웃·사용 흐름의 참고자료일 뿐 필드·필수값·상태코드의
정답이 아니다. 이 문서는 현재 영역의 공개 UI 계약만 정의한다. Wave 경계의
단일 원문은
[`01` §4](01_목적_범위_추진원칙_v1.5.md)이며 여기서 다시
요약하지 않는다. 후속 Wave 메뉴의 자리나 비활성 stub을 Wave 1 완료조건으로
만들지 않는다.

사이드바 메뉴 구성과 각 메뉴의 화면 소속은 이 문서 §2가 소유한다. 기술 정본은
라우팅·보안 구현만 소유하며 별도 메뉴 목록을 만들지 않는다.

## 1. 전역 UI 계약

### 1.1 프레임과 탐색

- 데스크톱 내부망 사용을 기준으로 기존 사이드바·상단바·작업영역 구조를 유지한다.
- 직원·수급자 이름을 선택하면 전환 toggle 없이도 목록을 잃지 않고 같은
  작업영역에 세부정보를 연다. 우측 분할패널 또는 목록과 공존하는 상세영역을
  사용하며 전체 페이지 이동이나 팝업을 일으키지 않는다.
- 브라우저 뒤로가기·닫기로 직전 검색어·필터·정렬·페이지를 복원한다.
- 월간 일정표는 `수급자` · `요양보호사` · `사회복지사` 3종으로 구분한다.
  같은 종류는 하나의 브라우저 팝업을 재사용하고, 다른 종류는 각각 하나씩
  동시에 열 수 있다. Wave 2 일정이 실제 존재하기 전에는 임의 일정을
  표시하지 않는다.
- 목록 정렬은 마지막 내부 PK까지 결정적으로 표시한다.
- 저장 중 중복 제출을 막고 성공·실패·충돌 상태를 명확히 알린다.

### 1.2 입력과 오류

- 라벨에서 필수/선택을 정확히 구분한다.
- 서버 업무 오류코드와 필드 오류를 임의 문자열로 바꾸지 않는다.
- 409 `row_version` 충돌 시 사용자 입력을 보존하고 최신값 재조회·재적용 선택을
  제공한다.
- 422 업무검증은 대상 행·기간·충돌 대상을 구조화하여 보여준다.
- legacy key·내부 mapping·민감 평문은 DOM·URL·다운로드에 노출하지 않는다.

### 1.3 접근성과 민감정보

- 키보드만으로 목록·탭·대화상자·저장·취소를 조작할 수 있어야 한다.
- 오류는 색상만으로 구분하지 않는다.
- 주민등록번호는 `birth_date`에서 만든 `YYMMDD-*******`만 기본 표시한다.
- 관리자 reveal은 일반 상세와 분리된 버튼·경고·step-up 대화상자를 제공하며
  [`05` §5.5](05_기술_보안_파일처리_아키텍처_v1.5.md#resident-security)의 security protocol을
  프론트 상태로 우회하거나 약화하지 않는다.
- 일반 화면에 평문 주민등록번호를 캐시하거나 유지하지 않는다.
- reveal 응답은 브라우저·TanStack Query·폼 상태·DOM snapshot에 보존하지 않고
  대화상자를 닫거나 화면을 이탈하면 즉시 폐기한다.

## 2. 메뉴별 Wave 1 화면

| 메뉴 | Wave 1 필수 화면 | Wave 1에서 제외 |

| 수급자 | 목록, 상세, 보호자, 납부자, 인정·등급, 혜택, 승인금액, 계약, 배정 | 일정·RFID·청구 |

선택지로 제공한다. 역할별 탭·역할별 중복 담당을 만들지 않는다.

## 3. 직원 화면

<a id="ui-staff-core"></a>

### 3.1 직원 목록

표시:

- 이름
- 재직번호
- 현재 재직상태
- 현재 직종
- 현재 업무역할 요약
- 마스킹된 연락처

휴대전화 마스크는 `010-****-5678`처럼 마지막 4자리만 남긴다. 다른 전화도
구분자는 유지할 수 있으나 가입자번호 마지막 4자리 외 숫자는 마스킹한다.

금지:

- legacy 직원키
- 평문 주민등록번호
- 구 시스템 별칭
- 별도 이관 근무상태

검색은 이름·재직번호·[`02` §3.2](02_업무규칙_계약_v1.1.md)의 전화 정규화
projection을 사용한다. legacy key 검색은 제공하지 않는다.

### 3.2 직원 기본정보

| 필드 | 상태 | 비고 |
|---|---|---|
| 이름 | 필수 | 직원 본체 |
| 주민등록번호 | 신규 일반직원 필수 | 기존 Wave 0/bootstrap 직원은 미등록 허용 |
| 주소 | 선택 |  |
| 전화번호 | 선택 | 화면용 원문 저장 |

입력 control은 [`02` §3.2](02_업무규칙_계약_v1.1.md)의
허용형식을 예시와 함께 안내하고 서버의 달력·세기·성별 오류를 해당 필드에
표시한다. 클라이언트가 별도 checksum 규칙을 추가하지 않는다. 저장 뒤에는
평문을 폼 default나 재조회 응답으로 돌려주지 않고, 기존 직원에 민감정보 행이
없다는 이유로 목록·상세 조회를 막지 않는다.

일반 수정화면에는 주민등록번호 input을 두지 않는다. 마스크는 조회용이며
빈 값 저장으로 번호를 삭제하거나 바꾸지 않는다. 별도 HIGH 정정 명령이
승인·구현되기 전에는 관리자도 일반 수정화면에서 번호를 교체할 수 없다.

일반 응답·화면에는 전화 정규화 projection과 legacy mapping을 노출하지 않는다.

### 3.3 재직·직종·역할

- 재직기간 목록과 새 재직 등록을 제공한다.
- 재입사는 기존 직원에 새 재직기간을 추가한다.
- 재직번호는 저장 transaction에서 발급되며 사용자가 직접 입력하지 않는다.
- 직종과 업무역할은 별도 기간 탭으로 표시한다.
- 재직기간 밖의 직종·역할을 저장하려 하면 대상 재직기간과 오류를 보여준다.

<a id="ui-staff-qualifications"></a>

### 3.4 자격증·서비스 제공자격

`자격증`과 `서비스 제공자격`을 별도 탭·폼·목록으로 제공한다.

자격증:

- 자격종류·자격번호·발급일을 관리한다.
- 자격 유효 시작일·종료일·만료일 입력을 만들지 않는다.
- 일반 원장은 3개 이상의 자격증도 등록할 수 있다.
- 초기등록 workbook의 최대 2개 입력범위를 일반 화면 제약으로 표시하지 않는다.
- 무효화/대체 이력을 표시하되 연결된 제공자격 기간을 자동종료하지 않는다.

서비스 제공자격:

- 재직기간·서비스종류·제공자격 시작일·선택 종료일을 관리한다.
- 안정 제공자격 ID를 숨겨진 업무참조로 유지하고, 선택적으로 같은 직원의
  근거 자격증을 연결한다.
- 자격증을 새로 만들지 않고 제공자격 기간만 추가할 수 있고, 자격증만 등록한
  채 제공자격 기간을 만들지 않는 것도 허용한다.
- 재직기간 밖 날짜는 대상 재직과 허용범위를 함께 표시하여 거부한다.
- 제공자격 종료일을 자격증 만료일로 표시하지 않는다.
- 이 제공자격 편집 제약과 Wave 2 일정 draft 허용을 혼동하지 않는다. 일정은
  재직·제공자격 밖 날짜도 draft로 저장할 수 있고 확정월에서 차단한다.

<a id="ui-recipient"></a>

## 4. 수급자 화면

### 4.1 수급자 목록

표시:

- 이름
- 수급자번호
- 생년월일
- 성별
- 현재 계약 서비스 요약

이름 저장값이 비어 있으면 목록·업무카드의 표시명은 정확히 `미입력`이다.

목록 행에 `recipient_status`(이용중/계약종료/대기중) 상태 문구를 표시하지 않는다.
상태 필터는 수동 태그 동등 비교이며, 계약 유효기간에서 상태를 추론하지 않는다.

필터:

- 선택지 순서: 이용중(`ACTIVE`) · 전체(`ALL`) · 계약종료(`ENDED`) · 대기중(`WAITING`)
- 화면 최초 진입 URL은 `status=ACTIVE`를 명시한다
- API에서 `status`를 생략하면 기본값은 `ALL`이다 (직접 API 호환)

선택 연락처를 보조 표시할 수 있다. 다음은 표시·검색·출력하지 않는다.

- `legacy_recipient_key`
- `legacy_attachment_key`
- 구 등록번호

### 4.2 수급자 기본정보

| 필드 | 상태 |
|---|---|
| 이름 | 선택 |
| 생년월일 | 선택 |
| 성별 | 선택 |
| 상태(`recipient_status`) | 필수(수동 태그). 표시: 이용중/계약종료/대기중. 값은 `ACTIVE`/`ENDED`/`WAITING` |
| 우편번호 | 선택 |
| 주소 | 선택 |
| 휴대전화 | **필수** |
| 메모 | 선택 |

`recipient_status`는 수급자에 붙는 메모성 수동 태그다. 기간·사유·이력 테이블이 없고
`recipient_contract`·서비스·마감·배정·알림과 자동 연동하지 않는다. 상세 기본정보
PATCH로만 변경하며, 생성 요청에는 상태를 넣지 않고 신규 수급자는 `ACTIVE`로 둔다.

자택전화 입력은 만들지 않는다. 최초 계약 전에는 수급자번호가 비어 있을 수
있으며 이를 오류로 표시하지 않는다.

### 4.3 보호자

- 보호자1·보호자2 두 슬롯만 제공한다.
- 이름·관계·전화번호·주소·이메일은 모두 선택이며 빈 값을 허용한다.
- 대표 보호자 표시·선택·기간·변경이력을 만들지 않는다.

삭제·비노출:

- 이름·전화번호·관계 필수표시
- 생년월일·성별 신규 입력
- 보호자3 추가 제어
- 대표 보호자 제어

### 4.4 본인부담금 납부자

- 보호자1·보호자2 중 납부자를 한 명 선택할 수 있다.
- 선택하지 않으면 수급자 본인을 납부자로 표시한다.
- 별도 납부자 입력폼·독립 snapshot·payer type·대표보호자 연동을 만들지 않는다.

삭제·비노출:

```text
독립 납부자 이름·전화·주소·관계 입력
SELF/PRIMARY_GUARDIAN payer type
대표보호자 유효성 검사
```

### 4.5 인정·등급

- 인정번호 입력 옆에 `L + 숫자 10자리`와 suffix 제거를 안내한다.
- 소문자 `l`과 `-100`류 입력은 preview에서 저장될 본번호를 보여준다.
- 인정 발급일은 필수 입력으로 표시하지 않는다.
- 등급 선택지는 `1`~`5`만 제공한다.
- 인지지원등급·자유입력 옵션을 제공하지 않는다.
- 각 인정기간 행 안에서 등급을 함께 입력·표시한다.
- `등급기간`·`등급유효기간`·`인정유효기간`이라는 별도 화면용어와 별도 원장을
  만들지 않고 모두 `인정기간`으로 표시한다.
- 기간중복·다른 본번호·타 수급자 소유 충돌을 구체적으로 표시한다.

### 4.6 혜택·승인금액

혜택:

- 고정 6종 코드의 한글 라벨을 제공한다.
- 수급자 생성 직후 자동생성된 `GENERAL`을 표시한다.
- 시작값은 날짜 입력이 아닌 원문 텍스트이며 최초값은 빈 문자열이다. 날짜 picker,
  날짜 검증, 마감 계산을 연결하지 않는다.
- 혜택 변경 시 현재값과 과거 대체이력을 구분해 표시한다.

지자체 승인금액:

- 혜택과 별도 탭·목록으로 제공한다.
- 원 단위 금액·시작일·종료일을 입력한다.
- 유효기간 중복을 차단하고 무효화/대체 이력을 표시한다.
- 월중 최고금액 계산 결과는 Wave 4 전에는 표시하지 않는다.

- 담당 공백기간은 `담당 없음`으로 표시한다.
- 월중 담당 변경을 허용한다.
- 선택 직원이 사회복지사 또는 간호사 직종이 아니면 저장을 차단한다.
- 실제 방문자 일치판정이나 방문 실행 입력은 Wave 3로 남긴다.

## 7. Wave 2 화면 분리

Wave 2에서 별도 구현:

- 공식 업무카드는 Dashboard에만 표시한다. 개인 할 일은 `사회복지사` 메뉴의
  달력형 일정표에만 표시한다. 두 목록을 한 화면에 합치지 않으며, 합침 API·
  브라우저 union을 만들지 않는다. 나중에 합침을 원하면 형님 사전 승인을 받는다.
- 공식 업무카드 업무목록은 `02` §9.3 봉인 다섯 가지뿐이다:
  1. 인정만료
  2. 계약만료
  3. 계획서통보
  4. 직원교체상담
  5. 신규직원업무
  다섯 가지 외 업무목록 추가·삭제는 형님 사전 승인이 필요하다.
- 업무카드 표시 정보는 `02` §9.3 봉인 다섯 가지뿐이다: 업무제목, 대상자이름,
  상세업무, 마감일, D-day. 다섯 가지 외 카드 정보 추가·삭제는 형님 사전
  승인이 필요하다.
- 사회복지사·간호사는 본인 카드만 보고 본인 카드만 닫는다. 닫기 제어는 카드
  정보 여섯 번째 항목이 아니다.
- 관리자는 자기 카드가 없고 모든 사회복지사·간호사의 열린 카드를 직원별로 묶어
  본다. 관리자는 열린 미완료 카드의 담당자만 바꿀 수 있고 대신 닫거나 완료하지
  않는다. 담당자 변경 대화상자는 업무종류, 대상자, 상세업무, 마감일, 현재
  담당자를 다시 보여 준 뒤 새 담당자만 고른다. 현재 담당자는 카드 본문 다섯
  정보에 넣지 않고 변경 대화상자에만 둔다. 매번 열 때 후보를 비우고 loading 중
  선택·확인을 막으며, 취소/이전 응답은 새 대화상자를 덮어쓰지 않는다. 409 최신
  snapshot에 카드가 없으면 대화상자를 닫고 페이지 수준 완료 안내만 남긴다.
- 닫힌 카드는 현재 목록에서 숨기며 재개방 제어를 만들지 않는다. 카드 진행률·
  상태·퍼센트·`WAITING`·`EXEMPT` 표시도 만들지 않는다.
- 대상자 이름이 비어 있으면 정확히 `미입력`으로 표시한다.
- Dashboard 다가오는 마감일은 세로영역을 사용해 페이지당 최소 15건을 표시하고,
  15건을 초과할 때만 페이지 이동을 노출한다.
- 개인 할 일은 생성자 본인만 조회·생성·수정·완료 토글·완전 삭제할 수 있다.
  완료는 별도 상태명/enum 없이 토글하며, 완료된 줄은 회색의 연한 글씨로
  표시한다. 순서는 드래그로 변경한다. 관리자 대행은 없다. Dashboard에는
  개인 할 일을 표시하지 않는다.
- `사회복지사` 달력형 일정표 편집창은 로그인 사용자별로 한 번에 하나만 연다.

  보여준다.
- 계획서 통보일·적용 시작일·적용 종료일(계획서 원장; 공식 카드 중

  `계획서통보`는 작성마감일 D-45에 표시한다.
- 세 갱신 카드의 자동 담당자는 표시·요청 시각이 아니라 위 원천이 확정한 카드
  `due_date` 업무기준일의 월 전문직 담당으로 서버가 배정한다. 같은 갱신묶음의

## 8. OpenAPI 소비·DOM 계약

- OpenAPI 생성 타입이 폼과 응답 타입의 기술 원본이다.
- 생성 타입 직접수정을 금지한다.
- 선택값은 UI·OpenAPI·DB nullability가 일치해야 한다.
- 공통 오류 봉투·HTTP 상태·안정 코드는
  [05 §3](05_기술_보안_파일처리_아키텍처_v1.5.md#api-contract)만 소유한다.
  UI는 생성 타입으로 봉투를 해석하고 `field_errors`는 해당 입력 옆에,
  `details`의 충돌 대상·기간·현재 version은 오류 요약에 표시한다.
- 409에서는 사용자 입력을 보존하고 서버 최신값과 필드별 차이를 보여준다.
  비충돌 필드만 재적용할 수 있으며 동일 필드 충돌은 사용자 선택 없이
  덮어쓰지 않는다.
- 일정 원장의 409는 자동 필드 재적용 대상이 아니다. 최신 snapshot을 다시 보여
  주되 사용자의 미저장 입력을 별도로 보존한다.
- forbidden 필드는 hidden input·테스트 fixture·mock 응답에도 두지 않는다.
- 자격증과 서비스 제공자격은 서로 다른 named OpenAPI model·endpoint·폼을
  사용한다. 건강검진·직원 분기상담·Wave 2 교체상담도 서로 다른 model이다.
- DOM 계약은 이름 control 활성화 뒤 목록 row·검색어·필터·정렬·페이지가
  그대로 있고 같은 workspace의 상세 region만 바뀌며 `window.open`이 호출되지
  않음을 검증한다.
- Playwright는 직원과 수급자 각각에서 목록→이름 선택→다른 이름 선택→뒤로가기
  흐름의 목록 문맥 보존을 검증한다.
- Wave 1 DOM과 Playwright에는 `월간 일정 열기`가 없다. Wave 2 일정 원장이
  존재하는 fixture에서는 별도 버튼 활성화가 새 동일출처 popup을 정확히 1개
  열고, 이름 control 활성화는 popup을 0개 여는지 검증한다.
- 민감 reveal DOM/Playwright는 POST·CSRF·현재 PIN step-up, no-store, 성공
  1회당 access event 1건과 dialog 종료 뒤 평문 DOM 부재를 검증한다.
- 필수/선택 라벨과 stale 재실행도 DOM 계약테스트로 고정한다.
