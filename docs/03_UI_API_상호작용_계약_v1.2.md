> 업무 의미: [`02_업무규칙_계약_v1.1.md`](02_업무규칙_계약_v1.1.md)

## 0. 적용 경계

기존 화면은 레이아웃·사용 흐름의 참고자료일 뿐 필드·필수값·상태코드의
정답이 아니다. 이 문서는 현재 영역의 공개 UI 계약만 정의한다. Wave 경계의
단일 원문은
[`01` §4](01_목적_범위_추진원칙_v1.5.md)이며 여기서 다시
요약하지 않는다. 후속 Wave 메뉴의 자리나 비활성 stub을 Wave 1 완료조건으로
만들지 않는다.

사이드바 메뉴 구성과 각 메뉴의 화면 소속은 이 문서 §2가 소유한다. 기술 정본은
라우팅·보안 구현만 소유하며 별도 메뉴 목록을 만들지 않는다.

## 1. 전역 UI 계약

### 1.1 프레임과 탐색

- 데스크톱 내부망 사용을 기준으로 기존 사이드바·상단바·작업영역 구조를 유지한다.
- 직원·수급자 이름을 선택하면 전환 toggle 없이도 목록을 잃지 않고 같은
  작업영역에 세부정보를 연다. 우측 분할패널 또는 목록과 공존하는 상세영역을
  사용하며 전체 페이지 이동이나 팝업을 일으키지 않는다.
- 브라우저 뒤로가기·닫기로 직전 검색어·필터·정렬·페이지를 복원한다.
- 월간 일정표는 `수급자` · `요양보호사` · `사회복지사` 3종으로 구분한다.
  같은 종류는 하나의 브라우저 팝업을 재사용하고, 다른 종류는 각각 하나씩
  동시에 열 수 있다. Wave 2 일정이 실제 존재하기 전에는 임의 일정을
  표시하지 않는다.
- 목록 정렬은 마지막 내부 PK까지 결정적으로 표시한다.
- 저장 중 중복 제출을 막고 성공·실패·충돌 상태를 명확히 알린다.

### 1.2 입력과 오류

- 라벨에서 필수/선택을 정확히 구분한다.
- 서버 업무 오류코드와 필드 오류를 임의 문자열로 바꾸지 않는다.
- 409 `row_version` 충돌 시 사용자 입력을 보존하고 최신값 재조회·재적용 선택을
  제공한다.
- 422 업무검증은 대상 행·기간·충돌 대상을 구조화하여 보여준다.
- legacy key·내부 mapping·민감 평문은 DOM·URL·다운로드에 노출하지 않는다.

### 1.3 접근성과 민감정보

- 키보드만으로 목록·탭·대화상자·저장·취소를 조작할 수 있어야 한다.
- 오류는 색상만으로 구분하지 않는다.
- 주민등록번호는 `birth_date`에서 만든 `YYMMDD-*******`만 기본 표시한다.
- 관리자 reveal은 일반 상세와 분리된 버튼·경고·step-up 대화상자를 제공하며
  [`05` §5.5](05_기술_보안_파일처리_아키텍처_v1.5.md#resident-security)의 security protocol을
  프론트 상태로 우회하거나 약화하지 않는다.
- 일반 화면에 평문 주민등록번호를 캐시하거나 유지하지 않는다.
- reveal 응답은 브라우저·TanStack Query·폼 상태·DOM snapshot에 보존하지 않고
  대화상자를 닫거나 화면을 이탈하면 즉시 폐기한다.

## 2. 메뉴별 Wave 1 화면

| 메뉴 | Wave 1 필수 화면 | Wave 1에서 제외 |
|---|---|---|
| 직원 | 목록, 상세, 재직, 직종·역할, 자격, 교육, 검진, 분기상담 | 업무카드 대시보드 노출 |
| 수급자 | 목록, 상세, 보호자, 납부자, 인정·등급, 혜택, 승인금액, 계약, 배정 | 일정·RFID·청구 |
| 사회복지사 | 전문직 담당 workspace의 사회복지사·간호사 역할별 탭 | 실제 방문 실행 |
| 대시보드 | Wave 0 기반 유지 | Wave 2 업무카드 신규 구현 |
| 본인부담금 | Wave 0 상태 유지 | Wave 4 계산·청구 신규 구현 |
| 입출력 | 문서상 경계만 유지 | Wave 3 실제 parser·run |
| 파일함 | 문서상 경계만 유지 | Wave 5 파일함·OCR |
| 설정 | Wave 0 상태 유지 | Wave 1 신규 구현 없음 |

사이드바 최상위 메뉴는 위 8개를 유지하며 간호사 메뉴를 별도로 추가하지 않는다.
대신 `사회복지사` 메뉴 안에서 `SOCIAL_WORKER`와 `NURSE` 탭·권한·배정목록을
분리한다. 각 역할은 자기 배정을 변경하고, 업무 조율에 필요한 상대 역할의 담당
수급자·월 일정은 read-only로만 조회한다. 관리자는 두 역할을 모두 관리할 수 있다.

## 3. 직원 화면

<a id="ui-staff-core"></a>

### 3.1 직원 목록

표시:

- 이름
- 재직번호
- 현재 재직상태
- 현재 직종
- 현재 업무역할 요약
- 마스킹된 연락처

휴대전화 마스크는 `010-****-5678`처럼 마지막 4자리만 남긴다. 다른 전화도
구분자는 유지할 수 있으나 가입자번호 마지막 4자리 외 숫자는 마스킹한다.

금지:

- legacy 직원키
- 평문 주민등록번호
- 구 시스템 별칭
- 별도 이관 근무상태

검색은 이름·재직번호·[`02` §3.2](02_업무규칙_계약_v1.1.md)의 전화 정규화
projection을 사용한다. legacy key 검색은 제공하지 않는다.

<a id="ui-staff-sensitive"></a>

### 3.2 직원 기본정보

| 필드 | 상태 | 비고 |
|---|---|---|
| 이름 | 필수 | 직원 본체 |
| 주민등록번호 | 신규 일반직원 필수 | 기존 Wave 0/bootstrap 직원은 미등록 허용 |
| 주소 | 선택 |  |
| 전화번호 | 선택 | 화면용 원문 저장 |

입력 control은 [`02` §3.2](02_업무규칙_계약_v1.1.md)의
허용형식을 예시와 함께 안내하고 서버의 달력·세기·성별 오류를 해당 필드에
표시한다. 클라이언트가 별도 checksum 규칙을 추가하지 않는다. 저장 뒤에는
평문을 폼 default나 재조회 응답으로 돌려주지 않고, 기존 직원에 민감정보 행이
없다는 이유로 목록·상세 조회를 막지 않는다.

일반 수정화면에는 주민등록번호 input을 두지 않는다. 마스크는 조회용이며
빈 값 저장으로 번호를 삭제하거나 바꾸지 않는다. 별도 HIGH 정정 명령이
승인·구현되기 전에는 관리자도 일반 수정화면에서 번호를 교체할 수 없다.

일반 응답·화면에는 전화 정규화 projection과 legacy mapping을 노출하지 않는다.

<a id="ui-staff-employment"></a>

### 3.3 재직·직종·역할

- 재직기간 목록과 새 재직 등록을 제공한다.
- 재입사는 기존 직원에 새 재직기간을 추가한다.
- 재직번호는 저장 transaction에서 발급되며 사용자가 직접 입력하지 않는다.
- 직종과 업무역할은 별도 기간 탭으로 표시한다.
- 재직기간 밖의 직종·역할을 저장하려 하면 대상 재직기간과 오류를 보여준다.

<a id="ui-staff-qualifications"></a>

### 3.4 자격증·서비스 제공자격

`자격증`과 `서비스 제공자격`을 별도 탭·폼·목록으로 제공한다.

자격증:

- 자격종류·자격번호·발급일을 관리한다.
- 자격 유효 시작일·종료일·만료일 입력을 만들지 않는다.
- 일반 원장은 3개 이상의 자격증도 등록할 수 있다.
- 초기등록 workbook의 최대 2개 입력범위를 일반 화면 제약으로 표시하지 않는다.
- 무효화/대체 이력을 표시하되 연결된 제공자격 기간을 자동종료하지 않는다.

서비스 제공자격:

- 재직기간·서비스종류·제공자격 시작일·선택 종료일을 관리한다.
- 안정 제공자격 ID를 숨겨진 업무참조로 유지하고, 선택적으로 같은 직원의
  근거 자격증을 연결한다.
- 자격증을 새로 만들지 않고 제공자격 기간만 추가할 수 있고, 자격증만 등록한
  채 제공자격 기간을 만들지 않는 것도 허용한다.
- 재직기간 밖 날짜는 대상 재직과 허용범위를 함께 표시하여 거부한다.
- 제공자격 종료일을 자격증 만료일로 표시하지 않는다.

### 3.5 교육·검진·분기상담

<a id="ui-staff-training"></a>

#### 3.5.1 교육 화면

- 신규직원교육은 재직기간별 `신규직원교육` 1행과 완료 checkbox로 표시한다.
- 정기교육은 [`02` §3.3](02_업무규칙_계약_v1.1.md)의
  exact code·표시명·cycle 7종을 축약·번역하지 않고 대상기간별 완료
  checkbox로 표시한다.
- 보수교육은 현재 요양보호사 직종인 직원에게만 선택 연도와
  출생연도의 홀짝 대상 여부를 표시한다. 자격증의 최초 취득연도부터
  2년이 경과한 해의 말일까지는 완료 checkbox 대신 면제를 표시한다.

- 같은 반기·연도에 재입사해도 정기교육 완료 checkbox는 유지한다.
- 교육시간·이수일자·이수센터·증빙파일 입력을 만들지 않는다.
- 완료와 완료해제 모두 저장 사용자·시각이 감사된다는 상태를 사용자에게 알린다.

<a id="ui-staff-health"></a>

#### 3.5.2 건강검진 화면

- 건강검진은 `검진사실`과 `대상별 상태`를 분리해 표시한다. 검진사실에서는
  검진일·선택 검진유형·선택 결과메모·선택 재직을 조회·등록한다.
- 대상별 상태는 `COMPLETE`/`INCOMPLETE`/`EXEMPT`를 표시한다. 완료는 같은
  직원의 검진사실, 미완료는 검진사실 없음, 면제는 면제사유를 보여준다.
- 공식 기준이 동결되기 전에는 신규입사·기존·재입사 대상의 자동생성,
  D-day·업무카드 제어와 공개 대상행 생성 control을 만들지 않는다.
  `target_key`·규칙버전은 시스템 소유 read-only 값이며 기존 상태행의
  표시·이력은 숨기지 않는다.

<a id="ui-staff-quarterly"></a>

#### 3.5.3 직원 분기상담 화면

- 분기상담은 달력연도·분기와 `COMPLETE`/`INCOMPLETE`/`EXEMPT` 상태를
  관리한다. 완료는 상담일·처리내용, 미완료는 미완료 사유, 면제는 면제 사유를
  각각 필수로 전환하고 다른 조건부 필드는 숨기거나 비운다.
- 직원 분기상담 화면과 Wave 2 요양보호사 교체상담 화면은 메뉴·제목·API를
  공유하지 않는다.
- 검진·분기상담의 증빙 첨부 제어는 Wave 5 전에는 만들지 않는다.

<a id="ui-recipient"></a>

## 4. 수급자 화면

### 4.1 수급자 목록

표시:

- 이름
- 수급자번호
- 생년월일
- 성별
- 현재 계약 서비스 요약

목록 행에 `recipient_status`(이용중/계약종료/대기중) 상태 문구를 표시하지 않는다.
상태 필터는 수동 태그 동등 비교이며, 계약 유효기간에서 상태를 추론하지 않는다.

필터:

- 선택지 순서: 이용중(`ACTIVE`) · 전체(`ALL`) · 계약종료(`ENDED`) · 대기중(`WAITING`)
- 화면 최초 진입 URL은 `status=ACTIVE`를 명시한다
- API에서 `status`를 생략하면 기본값은 `ALL`이다 (직접 API 호환)

선택 연락처를 보조 표시할 수 있다. 다음은 표시·검색·출력하지 않는다.

- `legacy_recipient_key`
- `legacy_attachment_key`
- 구 등록번호

### 4.2 수급자 기본정보

| 필드 | 상태 |
|---|---|
| 이름 | 필수 |
| 생년월일 | 필수 |
| 성별 | 필수 |
| 상태(`recipient_status`) | 필수(수동 태그). 표시: 이용중/계약종료/대기중. 값은 `ACTIVE`/`ENDED`/`WAITING` |
| 우편번호 | 선택 |
| 주소 | 선택 |
| 자택전화 | 선택 |
| 휴대전화 | 선택 |

`recipient_status`는 수급자에 붙는 메모성 수동 태그다. 기간·사유·이력 테이블이 없고
`recipient_contract`·서비스·마감·배정·알림과 자동 연동하지 않는다. 상세 기본정보
PATCH로만 변경하며, 생성 요청에는 상태를 넣지 않고 신규 수급자는 `ACTIVE`로 둔다.

자택전화와 휴대전화를 같은 입력 하나로 합치지 않는다. 최초 계약 전에는
수급자번호가 비어 있을 수 있으며 이를 오류로 표시하지 않는다.

### 4.3 보호자

- 수급자당 0명 이상을 목록으로 관리한다.
- 이름만 필수로 표시한다.
- 전화번호·주소·관계는 선택이며 빈 값 저장을 허용한다.
- 대표 보호자 0명을 허용한다.
- 대표 지정·변경 시 유효기간과 변경 이력을 보여준다.
- 같은 시점에 대표 2명을 지정하려 하면 저장 전후 모두 차단한다.

삭제·비노출:

- 전화번호 필수표시
- 관계 필수표시
- 생년월일·성별 신규 입력
- 대표 보호자 없음을 수급자 저장 오류로 처리

### 4.4 본인부담금 납부자

- 납부자 없음과 독립 납부자 1명 입력을 지원한다.
- 행을 만들 때 이름만 필수다.
- 전화번호·주소·관계는 선택이다.
- 보호자 선택기·대표보호자 복사 강제·payer type 선택을 제공하지 않는다.
- 편의를 위한 값 복사 동작을 제공하더라도 복사 뒤 독립 snapshot임을 명시하고
  FK나 자동동기화를 만들지 않는다.

삭제·비노출:

```text
SELF
PRIMARY_GUARDIAN
guardian_id
대표보호자 유효성 검사
```

### 4.5 인정·등급

- 인정번호 입력 옆에 `L + 숫자 10자리`와 suffix 제거를 안내한다.
- 소문자 `l`과 `-100`류 입력은 preview에서 저장될 본번호를 보여준다.
- 인정 발급일은 필수 입력으로 표시하지 않는다.
- 등급 선택지는 `1`~`5`만 제공한다.
- 인지지원등급·자유입력 옵션을 제공하지 않는다.
- 인정기간과 그 안의 등급기간을 타임라인 또는 표로 표시한다.
- 기간중복·다른 본번호·타 수급자 소유 충돌을 구체적으로 표시한다.

### 4.6 혜택·승인금액

혜택:

- 고정 6종 코드의 한글 라벨을 제공한다.
- 시작일·종료일과 무효화/대체 상태를 표시한다.
- 서로 다른 혜택 코드라도 기간중복을 차단한다.
- 자료 없음은 빈 상태이며 `GENERAL` 자동생성 버튼을 두지 않는다.

지자체 승인금액:

- 혜택과 별도 탭·목록으로 제공한다.
- 원 단위 금액·시작일·종료일을 입력한다.
- 유효기간 중복을 차단하고 무효화/대체 이력을 표시한다.
- 월중 최고금액 계산 결과는 Wave 4 전에는 표시하지 않는다.

## 5. 계약 화면

### 5.1 서비스 선택

| 그룹 | 서비스 |
|---|---|
| 장기요양 | 방문요양, 방문목욕 |
| 지역돌봄 연계 | 일시재가, 병원동행 |
| 바로돌봄 | 바로돌봄 |

서비스별 독립 계약을 등록한다. 같은 그룹의 다른 서비스는 동시이용을 허용하고
다른 그룹 기간중복은 차단한다.

### 5.2 계약 필드

| 필드 | 상태 | 표시 규칙 |
|---|---|---|
| 서비스종류 | 필수 | 5종 |
| 계약 시작일 | 필수 |  |
| 계약 종료일 | 선택 |  |
| 급여개시일 | 선택 | 참고정보 |
| 서명자 이름 | 선택 | snapshot |
| 서명자 관계 | 선택 | snapshot |
| 서명자 전화번호 | 선택 | snapshot |
| 종료사유 | 선택 | 자유입력 |

- 계약번호 입력·필수표시·자동채번 UI를 만들지 않는다.
- 종료사유는 빈 값을 허용하고 `사망`은 선택 제안값일 수만 있다.
- `사망`을 기본값으로 넣거나 과거 빈 값을 자동보정하지 않는다.
- 급여개시일 누락 경고가 있더라도 저장·후속 업무를 차단하지 않는다.
- 서명자에서 보호자·납부자 FK 선택기를 제공하지 않는다.
- 종료된 계약의 재활성화 대신 새 계약 등록을 안내한다.

### 5.3 인정 전환

필수 단계:

1. 새 인정 본번호·기간·등급과 대체 서비스별 계약을 입력한다.
2. preview에서 종료 대상 인정·등급·계약, 서비스 multiset, 제안 종료일을 표시한다.
3. 사용자 명시 확인을 받는다.
4. apply 결과 또는 stale 409를 표시한다.

- preview 없이 apply할 수 없다.
- 누락 대체계약·중복·서비스 multiset 불일치는 422로 표시한다.
- stale 409에서는 기존 preview를 폐기하고 최신자료로 재실행한다.
- 부분 성공처럼 보이는 화면 상태를 만들지 않는다.

## 6. 배정 화면

### 6.1 요양보호사 배정

- 계약별 일반·가족요양 기간배정을 관리한다.
- 가족요양은 관계 snapshot을 필수로 받는다.
- 같은 계약·직원 기간중복을 차단한다.
- 여러 일반 제공자 동시배정을 허용한다.
- 배정변경 UI에서 직원교체 상담 케이스를 생성하거나 암시하지 않는다.

### 6.2 사회복지사·간호사 월 담당

- 역할별 탭에서 수급자·서비스월의 현재 담당과 변경 history를 함께 표시한다.
- 같은 수급자·서비스월에 사회복지사와 간호사가 각각 존재할 수 있고, 어느
  역할의 공백기간도 `담당 없음`으로 표시한다.
- 월중 담당 변경을 허용한다.
- 해당 업무역할이 유효하지 않거나 다른 역할의 변경 권한이 없으면 저장을 차단한다.
- 실제 방문자 일치판정이나 방문 실행 입력은 Wave 3로 남긴다.

## 7. Wave 2 화면 분리

Wave 2에서 별도 구현:

- 공식 업무카드와 개인 할 일을 구분해 한 화면에서 표시
- 공식 상태 `COMPLETE`/`INCOMPLETE`/`EXEMPT`/`WAITING`, 발생이유,
  기한과 D-day
- 단계별 완료와 필수 단계 전체완료 후 최종완료
- 사회복지사·간호사 공식 카드의 해당 월 담당 수급자 범위 제한
- 계획서 통보일·적용 시작일·적용 종료일
- 작성마감일(지난 통보일+6개월, 계약종료일·인정 종료일 중 빠른 날짜로 cap,
  `02` §9.1, 2026-08-09 결정) D-100 내부 업무와 D-45 메인 카드
- 기간 불일치·연결 부족은 저장을 거부하는 오류로 표시(경고 후 저장 허용 아님)
- 일정 원장과 확정월 잠금
- 상세영역의 명시적 `월간 일정 열기` 팝업 동작
- 방문목욕 일정의 서로 다른 요양보호사 정확히 2명
- 일정 WARNING의 확인자·확인시각 표시
- 일괄취소 대상·건수 preview, 최종확인, 실제근무 일정 제외
- 확정월 해제 사유 입력과 해제·정정·재확정 이력
- 실제 급여제공 순서 기반 직원교체 케이스
- Day 1~14 상담기한과 Day 14 재교체 예외
- 실제근무 정정 후 재판정

Wave 1 배정 변경 화면이나 계약 화면에서 위 상태를 임시로 생성하지 않는다.
실제근무 증거는 Wave 3 소유이므로 Wave 2 일괄취소 UI는 연결된 증거를 존중하되
가짜 실제근무 행을 만들지 않는다. 계획서의 반기 종료일·계약/인정 cap과 실제
급여제공 순서 기반 직원교체가 각각 과거 통보일+6개월 월말·배정변경 감지 의미를
대체한다.

## 8. OpenAPI 소비·DOM 계약

- OpenAPI 생성 타입이 폼과 응답 타입의 기술 원본이다.
- 생성 타입 직접수정을 금지한다.
- 선택값은 UI·OpenAPI·DB nullability가 일치해야 한다.
- 공통 오류 봉투·HTTP 상태·안정 코드는
  [05 §3](05_기술_보안_파일처리_아키텍처_v1.5.md#api-contract)만 소유한다.
  UI는 생성 타입으로 봉투를 해석하고 `field_errors`는 해당 입력 옆에,
  `details`의 충돌 대상·기간·현재 version은 오류 요약에 표시한다.
- 409에서는 사용자 입력을 보존하고 서버 최신값과 필드별 차이를 보여준다.
  비충돌 필드만 재적용할 수 있으며 동일 필드 충돌은 사용자 선택 없이
  덮어쓰지 않는다.
- forbidden 필드는 hidden input·테스트 fixture·mock 응답에도 두지 않는다.
- 자격증과 서비스 제공자격은 서로 다른 named OpenAPI model·endpoint·폼을
  사용한다. 건강검진·직원 분기상담·Wave 2 교체상담도 서로 다른 model이다.
- DOM 계약은 이름 control 활성화 뒤 목록 row·검색어·필터·정렬·페이지가
  그대로 있고 같은 workspace의 상세 region만 바뀌며 `window.open`이 호출되지
  않음을 검증한다.
- Playwright는 직원과 수급자 각각에서 목록→이름 선택→다른 이름 선택→뒤로가기
  흐름의 목록 문맥 보존을 검증한다.
- Wave 1 DOM과 Playwright에는 `월간 일정 열기`가 없다. Wave 2 일정 원장이
  존재하는 fixture에서는 별도 버튼 활성화가 새 동일출처 popup을 정확히 1개
  열고, 이름 control 활성화는 popup을 0개 여는지 검증한다.
- 민감 reveal DOM/Playwright는 POST·CSRF·현재 PIN step-up, no-store, 성공
  1회당 access event 1건과 dialog 종료 뒤 평문 DOM 부재를 검증한다.
- 필수/선택 라벨과 stale 재실행도 DOM 계약테스트로 고정한다.
