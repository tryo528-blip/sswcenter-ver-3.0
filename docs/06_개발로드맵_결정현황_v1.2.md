> 기준일: 2026-08-13 KST
> 지위: 개발순서·착수/승격 gate·미결 결정 register의 단일 정본
> 대체: `07_개발로드맵_및_결정현황_v1.0.md`

## 🚨 형님 승인 절대 게이트
> **형님 승인 없이 어떠한 계약도 추가하거나 삭제하지 않는다.**
> 업무·UI·API·DB·기술·보안·로드맵 계약은 형님 사전 승인을 받은 정본 개정으로만 추가·삭제·변경한다.

## 0. 사용법

- 이 문서는 **언제 무엇을 구현하고 언제 어떤 gate를 통과할지**만 정한다.
- 업무·UI·DB·기술 본문은 02~05에 두고 여기서 복사하지 않는다.
- 현재 작업상태·기준 SHA·담당자·실행명령·결과수치는 활성 작업 패킷과
  `review/` 증거가 소유한다.
- 활성 패킷은 이 문서 전체가 아니라 해당 작업행과 02~05의 최하위 계약
  anchor, matrix ID만 지정해야 한다.

## 1. 개발 순서

```text
검증된 Wave 0
→ W1A 직원
→ W1B 수급자·보호자·납부자 선택
→ W1C 인정기간+등급·혜택·승인금액
→ W1D 서비스계약
→ W1E 요양보호사 배정·월 전문직 담당
→ W1F Wave 1 통합 봉인
→ W2A 급여계획서·계획서통보 날짜 원천
→ W2B 공용 일정 원장·확정월·동시성
→ W2C 개인 할 일 원장·사회복지사 달력형 일정표
→ W2D 공식 업무카드 원장·Dashboard(인정만료·계약만료·계획서통보·직원교체상담·신규직원업무)
→ Wave 3 공단·RFID·실제근무
→ Wave 4 계산·청구·수납
→ Wave 5 파일함·OCR·출력·복구 완성
```

- 이전 제품 code·migration을 가져오지 않고 현재 정본에서 구현한다.
- 각 Wave는 직전 승격 PASS SHA의 새 Alembic revision chain으로 이어진다.
- W1A~W1E는 순서가 기본이며, 병행 가능 여부와 AI 역할·write 책임 분리는
  [AI 운영·업무분담 정본](../00-오케스트레이션-작업지침.md)을 따른다.
- W1F PASS 전 Wave 2 제품 구현을 승격하지 않는다.

## 3. gate와 증거

### 3.1 마이크로슬라이스

- 마이크로슬라이스의 Writer 선정·write 책임·독립검수·승격 절차는
  [AI 운영·업무분담 정본](../00-오케스트레이션-작업지침.md)을 따른다.
- 제품 영향태그별 gate와 의존 순서는 이 문서의 Wave 경계와 활성 제품 패킷을 따른다.
- 업무·UI·DB 정본에는 실행명령·PASS 수치·현재 SHA를 기록하지 않는다.

### 3.2 W1F 통합 봉인

고정 후보 SHA의 별도 clean worktree에서 다음 계층을 통과한다.

- Wave 0 → 전체 Wave 1 migration chain, fresh upgrade와 복구절차
- PostgreSQL catalog·FK·CHECK·exclusion·trigger·동시성
- backend 전체 회귀·lint·type check
- OpenAPI 재생성 drift 없음
- frontend unit·lint·build
- 실제 FastAPI·PostgreSQL·Playwright desktop E2E
- leak·민감평문 부재
- backup·restore 뒤 DB↔파일 무결성
- Wave 2 이상 구조 선구현 부재

결과는 `PASS`, `FAIL`, `BLOCKED`다. W1F PASS 후보만 Wave 2 기반으로
승격할 수 있다.

### 3.3 테스트 matrix 지위

[`review/WAVE1_CLEAN_TEST_MATRIX.md`](../review/WAVE1_CLEAN_TEST_MATRIX.md)는
정본이 아니라 이 문서가 지정한 gate의 실행 명세다. 테스트 ID·적용범위·
기대결과를 정본 계약에 연결하며 특정 실행의 SHA·수치는 소유하지 않는다.
matrix와 이 문서의 gate 시점·범위가 충돌하면 이 문서가 우선하고 matrix를
보정한다.

| W5-07 | 백업 경로·세대·암호키 운영 | `USER_DECISION_REQUIRED` | 경로·세대수·책임자·교체절차 | 운영 전 |
| W5-08 | 복원훈련 책임·허용시간 | `USER_DECISION_REQUIRED` | 관리자 / 이중확인 / 외부동석 | 운영 인수 전 |
| W5-09 | 파일함·감사원본·OCR 열람권한 | `USER_DECISION_REQUIRED` | 역할별 조회·다운로드·공개·예외승인 | 접근제어 전 |

## 10. 승격 원칙

- exact 후보 SHA와 검증결과가 일치해야 한다.
- review-only 증거 commit과 제품 implementation commit을 구분한다.
- 실패·미검증 후보를 정본 PASS·보호 브랜치·릴리스로 승격하지 않는다.
- 과거 branch를 일반 merge해 폐기 구현을 되살리지 않는다.
- 실제 ref 조작·tag·push는 선행 gate PASS와 사용자 권한 범위 안에서 수행한다.
