01 · 한눈에 보기

이번에 바뀐 결론

외부 업무앱 연동 전제는 폐기하고, 업무카드와 개인 할 일을 모두 ERP 안에서 관리하는 구조로 설계했습니다.

  • 공식 업무카드 원장과 개인 할 일 원장은 분리
  • 공식 카드는 Dashboard에만, 개인 할 일은 사회복지사 달력형 일정표에만 표시
  • 공식 업무목록 다섯 가지·카드 정보 다섯 가지로 봉인
  • 브라우저 저장소는 업무 원장으로 사용하지 않음
  • 합침 API·이중 fetch·결정적 union을 만들지 않음

02 · 핵심 설계

새 구조는 이렇게 단순합니다.

공식 업무카드

시스템이 만든 업무

업무별 원천 슬라이스가 발생 조건을 계산하고, ERP가 공식 업무카드를 저장·조회합니다. 표시 위치는 Dashboard입니다.

개인 할 일

사용자가 만든 업무

ERP 계정 소유의 별도 원장입니다. 사회복지사 달력형 일정표에서 생성자 본인만 봅니다.

공식 업무목록
  • 인정만료
  • 계약만료
  • 계획서통보
  • 직원교체상담
  • 신규직원업무

목록 밖 업무 또는 정보 추가·삭제는 형님 사전 승인 필요

카드 정보
  • 업무제목
  • 대상자이름
  • 상세업무
  • 마감일
  • D-day

목록 밖 업무 또는 정보 추가·삭제는 형님 사전 승인 필요

업무 원천

계획서 등 각 업무 슬라이스가 마감일을 계산합니다.

ERP 원장

공식 업무카드와 개인 할 일을 서버 DB에 분리 저장합니다.

화면 분리

공식 카드는 Dashboard, 개인 할 일은 사회복지사 달력형 일정표에만 표시합니다.

03 · 개인 할 일

최종 결정

  • 표시 위치: 사회복지사 메뉴 달력형 일정표 하나뿐
  • Dashboard에는 개인 할 일을 표시하지 않음
  • 생성·수정·완료 토글·삭제·조회는 생성자 본인만
  • 로그인한 다른 사람과 관리자에게 보이지 않음 · 관리자 대행 없음
  • 완료는 별도 상태명/enum 없이 토글 · 완료 줄은 회색의 연한 글씨
  • 삭제는 완전 삭제 · 순서는 드래그로 변경
