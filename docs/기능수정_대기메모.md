# 기능 수정 대기 메모

> 화면 디자인 수정과 기능 수정은 분리한다. 아래 항목은 요청사항만 기록하며, 별도 승인 전에는 기능/API/데이터 동작을 변경하지 않는다.

## 2026-08-04

- [ ] 대시보드 직원 업무 카운트(`2/3`)를 누르면 미완료 직원 명단을 조회·표시한다. 대상 업무, 명단 기준(미완료/미등록), 상세 화면 또는 필터 이동 경로를 확정한 뒤 구현한다.
- [ ] 업무 카드의 `1/2 완료` 진행률 기능을 제거할지 결정한다. 현재는 완료 상태 계산·상호작용 로직은 유지하고, 요청에 따라 진행률 텍스트만 화면에서 숨긴다.
- [ ] 다른 메뉴에서 대시보드로 이동할 때 발생하는 지연을 개선한다. 현재 대시보드 진입 시 직원 전체 목록을 먼저 순차 조회한 뒤 수급자 총계와 마감일을 추가 조회하는 구조이므로, 요청 시 네트워크 waterfall·렌더링 병목을 측정하고 병렬 조회/캐시/요약 API 적용 여부를 결정한다.
- [ ] 수급자 목록은 현재 너비를 유지하고 `이름 · 나이(만) · 등급 · 제공중 서비스` 네 항목만 표시한다. [디자인 반영] 네 항목 헤더와 만 나이(생년월일 기준) 표시를 추가했고, 등급·제공중 서비스는 기능 연결 전까지 `미지정` 자리값으로 표시한다. 현재 등급·활성 서비스는 W1C/W1D 요약 데이터 계약이 필요하므로 기능 작업 승인 후 목록 요약 응답 또는 별도 배치 조회로 연결한다.
- [ ] 수급자 목록의 페이지 이동 기능을 제거하고, 화면 아래까지 목록판을 확장한 뒤 목록 내부 스크롤로 탐색한다. [디자인 반영] 목록판을 남은 화면 높이까지 늘리고 `이전`·`다음` 표시를 숨겼다. 전체 목록 로딩 또는 무한 스크롤, 필터·선택 상태·성능 기준을 함께 확정해야 하므로 기능 작업 승인 후 구현한다.
- [ ] 수급자 목록 상태를 `이용중 → 전체 → 계약종료 → 대기중` 네 가지로 제공하고 선택 즉시 목록을 전환한다. [디자인 반영] 상단 영역을 `이름 검색창 · 수급자 등록 버튼 · 상태 선택창 · 선택 상태별 인원수` 구성으로 정리했고 선택지 문구와 순서를 변경했다. 다른 메뉴에서 수급자 목록으로 처음 진입해 상태 필터가 없을 때는 `이용중`을 기본으로 표시한다. 상단 총 인원도 선택한 상태에 맞는 총계로 갱신한다. 현재는 선택값을 URL에만 반영하고 목록 API 요청에는 상태 필터를 전달하지 않아 350명 총계가 상태별로 바뀌지 않는다. `대기중`은 이 목록에서만 사용하는 로컬 상태로, 이용 이력이 없거나 계약 종료 후 다시 이용하거나 신규 이용할 가능성이 높은 예비수급자를 표시하며 다른 기능에는 연결하지 않는다. 기능 작업 승인 후 기본값·상태 판정·API 파라미터·로딩·선택 상태 유지 기준을 확정한다.
- [ ] 수급자 목록 헤더를 `이름 · 만 나이 · 등급 · 제공중 서비스`로 구성하고 각 헤더 클릭으로 오름차순·내림차순을 전환한다. [디자인 반영] 기존 별도 정렬 컨트롤은 화면에서 제거했다. 현재 URL 정렬값·내부 정렬 로직은 기능 작업 승인 전까지 유지하며, 등급·서비스 정렬값을 포함한 목록 요약 계약을 기능 작업 승인 후 확정한다.
- [x] (원복/보류) 수급자번호를 이름 옆으로 옮기고 우측 자리에 인정번호를 넣는 안은 취소했다. 수급자번호·인정번호 등 식별 정보는 목록이 아니라 오른쪽 상세정보 패널에서 표시하는 기준으로 유지한다.
- [ ] 상세정보 요약에 현재 등급과 본인부담금 비율(%)을 표시한다. [디자인 반영] 표시 순서는 `생년월일 → 등급 → 인정번호 → 성별 → 휴대전화 → 본인부담금`으로 배치했고, 현재 등급·본인부담금은 모두 `미지정`으로 표시한다. W1C 등급·급여/감면 유효값을 같은 기준일로 조회하는 데이터 계약이 필요하므로 기능 작업 승인 후 연결한다.
- [x] `목록 유지` 버튼 동작 오류 수정: `detail`만 삭제해 `selected`가 남던 문제를 수정해 상세·선택만 해제하고 검색·필터·페이지는 유지한다.
- [x] 개발 로그인 우회 재진입 오류 수정: 개발 우회가 켜진 로컬 환경에서는 실제 시드 ADMIN 계정으로 보호 API를 처리하고, 세션 401 신호가 미리보기 계정을 로그인 화면으로 되돌리지 않도록 했다. 운영 환경에는 적용되지 않는다.
- [ ] 수급자 등록·수정 화면에 우편번호 검색 API를 연결한다. 도로명주소 제공처, API 키/허용 도메인, 선택 결과의 우편번호·주소 반영 및 저장 계약을 확정한 뒤 구현한다.
- [ ] 주소 입력을 `우편번호 · 도로명주소 · 상세주소` 세 칸으로 분리한다. 현재 단일 `address` 필드와의 호환/마이그레이션 및 API 저장·조회 계약을 우편번호 API 연동과 함께 확정한다.
- [x] 수급자 기본 화면: 수급자 기본정보 + 보호자1 + 보호자2 표시. 상단 단일 `수정`으로 함께 편집, `저장`/`취소`. 보호자별 등록/수정 버튼 없음. 신규 등록 흐름 보존.

### 이번 UI 요청으로 확인된 기능 메모

- [ ] 수급자 등록 API/DB가 현재 이름·생년월일·성별을 필수로 요구하므로, 휴대전화만 필수로 저장하려면 `RecipientCreateRequest`, `RecipientResponse`, `erp.recipient` 컬럼 및 마이그레이션 정책을 함께 변경해야 한다. 이번 작업은 UI 검증과 자체 입력 안내까지만 반영한다.
- [ ] 보호자 이름·관계를 선택 입력으로 저장하려면 현재 `GuardianCreateRequest`/DB의 이름 필수 제약을 완화해야 한다. 전화번호·주소·이메일은 각각 문자발송·라벨출력·이메일 자동발송 연계 기능을 별도 확정하고 API/데이터 계약에 반영한다.
- [ ] 수급자·보호자 주소 영역을 우편번호·앞주소·뒷주소로 분리 저장하고, 주소 클릭 시 우편번호 검색 API를 연결한다. 현재 수급자 API는 `postal_code`와 단일 `address`, 보호자 API는 단일 `address`만 제공하므로 주소 분리 스키마·검색 공급자·저장 계약 확정이 필요하다.
- [ ] 수급자 등급(1~5등급)과 본인부담금(기초·6%·9%·15%)을 저장·조회하려면 현재 Recipient API/DB에 해당 필드와 계약이 없어 스키마·마이그레이션·응답 표시를 확정한다. 이번 작업은 등록 화면 선택 UI만 반영한다.
- [ ] 수급자 목록은 현재 화면에서 15명 제한이 아니라 `PAGE_SIZE = 100`으로 API를 요청한다. 화면에 15명만 표시하는 기준으로 바꿀지, 페이지·스크롤·API page_size를 함께 확정한다.
