# 오퍼레이터 테스트·검수 등급 정의 v1.0

> 소유 영역: Codex/Claude Code 오퍼레이터가 테스트·검수 범위를 선택할 때 사용하는 등급의 의미
> 기준일: 2026-08-12 KST

이 문서는 등급의 작업 범위와 의미만 정의한다. 모델·effort·fast 배정과 호출 권한은 [`00-오케스트레이션-작업지침.md`](../00-오케스트레이션-작업지침.md)가 소유하고, wrapper와 라우팅 스킬은 그 결정을 구현한다.

## 1. 테스트 등급

| 등급 | 의미·대표 범위 |
|---:|---|
| 1 | 정적·문법·import·compile·단일 smoke |
| 2 | bounded unit·component·contract |
| 3 | 격리 PostgreSQL·DB integration |
| 4 | API·frontend·service·E2E |
| 5 | 운영·복구·migration lifecycle·security·최종 acceptance |

## 2. 검수 등급

| 등급 | 의미·대표 범위 |
|---:|---|
| 1 | 빠른 집중 검수 |
| 2 | 일반 정확성·회귀·테스트 적정성 검수 |
| 3 | cross-layer·data flow·integration·edge 검수 |
| 4 | architecture·security·concurrency·recovery·운영 검수 |
| 5 | 최종 adversarial acceptance 검수 |

## 3. 선정 규칙

- 요청 범위를 전부 포함하는 가장 낮은 등급을 우선 선택한다.
- 한 작업이 여러 범주를 포함하면 가장 높은 해당 등급을 선택한다.
- 모델 사용량이나 한도 때문에 등급을 낮추지 않는다. 범위를 낮출 수 있을 때만 작업을 분리한다.
- 테스트 등급과 검수 등급은 별도로 선택한다. 테스트가 끝났다고 같은 숫자의 검수가 자동으로 결정되는 것은 아니다.
- 범위를 넘어서는 운영·보안·복구 검증은 Grade 5 의미에 해당하므로 별도 명시와 독립 검수가 필요하다.

이 문서의 의미표를 변경할 때는 버전을 올리고, 기존 handoff·래퍼 문서에 표를 복사하지 말고 이 문서로 연결한다.
