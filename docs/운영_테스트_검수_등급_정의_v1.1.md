# AI 작업 테스트·검수 등급 정의 v1.1

> 소유 영역: 현재 actor가 선택할 테스트·검수 깊이의 의미
> 기준일: 2026-08-15 KST

이 문서는 등급의 작업 범위와 의미만 정의한다. Codex·Grok·DeepSeek 선택과 구현·검수·수정 action은 [`00-오케스트레이션-작업지침.md`](../00-오케스트레이션-작업지침.md)가 소유한다. 등급은 특정 actor나 모델에 고정되지 않는다.

## 1. 테스트 등급

| 등급 | 의미·대표 범위 |
|---:|---|
| 1 | 정적·문법·import·compile·단일 smoke |
| 2 | bounded unit·component·contract |
| 3 | 격리 PostgreSQL·DB integration |
| 4 | API·frontend·service·E2E |
| 5 | 운영·복구·migration lifecycle·security·최종 acceptance 증거 |

## 2. 검수 등급

| 등급 | 의미·대표 범위 |
|---:|---|
| 1 | 빠른 집중 검수 |
| 2 | 일반 정확성·회귀·테스트 적정성 검수 |
| 3 | cross-layer·data flow·integration·edge 검수 |
| 4 | architecture·security·concurrency·recovery·운영 검수 |
| 5 | 최종 adversarial acceptance 검수 |

## 3. 선정 규칙

- 요청 범위를 전부 포함하는 가장 낮은 등급을 우선 선택한다.
- 한 작업이 여러 범주를 포함하면 가장 높은 해당 등급을 선택한다.
- actor 사용량이나 한도 때문에 등급을 낮추지 않는다. 독립적으로 검증 가능한 경우에만 범위를 나눈다.
- 테스트 등급과 검수 등급은 별도로 선택한다. 테스트가 끝났다고 같은 숫자의 검수가 자동 결정되지 않는다.
- 범위를 넘어서는 운영·보안·복구 검증은 Grade 5 의미에 해당하므로 별도 범위와 독립 검수가 필요하다.
- 검수의 최소 단위는 파일이 아니라 하나의 완결된 slice다. 단일 파일이 독립 계약을 소유하는 경우에만 단일 파일 검수를 사용한다.
- 검수 action은 등급과 무관하게 read-only다.
- Grade 5 PASS는 해당 slice의 검수 증거일 뿐 W0~W2 전체 acceptance, 운영 수용, release 승인과 동일하지 않다.

이 의미표를 변경할 때는 버전을 올리고 다른 handoff·runner 문서에 표를 복사하지 말고 이 문서로 연결한다.
