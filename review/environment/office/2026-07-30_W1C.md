# W1C 사무실 환경 이슈 기록

- 기록일: 2026-07-30
- 환경 구분: `OFFICE`
- 기록 범위: 사무실 PC에서 발생하거나 재현된 항목만 기록
- 분리 원칙: 집 환경 기록(`HOME`)과 병합하거나 번호를 공유하지 않음
- 작업 경로: `C:\sswcenter\2.1`
- 작업 브랜치: `codex/w1c-certification-ledgers`
- 기준 환경: Windows, PowerShell, Python 3.11.9, Node.js 24.18.0

## 해결 완료

### OFFICE-ENV-001 — 이동한 작업 폴더에 로컬 의존성 환경 없음

- 증상: 새 작업 경로에 `backend\.venv`와 `frontend\node_modules`가 없어 검증 명령을 바로 실행할 수 없었다.
- 원인: 두 경로 모두 Git 추적 대상이 아닌 기기별 로컬 산출물이다.
- 조치: `backend\.venv`를 새로 만들고 Python 요구사항을 설치했으며, 프런트엔드는 `npm ci`로 잠금 파일과 일치하게 설치했다.
- 결과: 백엔드·프런트엔드 검증 명령 정상 실행.

### OFFICE-ENV-002 — Windows PowerShell 경유 OpenAPI 한글 인코딩 손상

- 증상: OpenAPI JSON을 PowerShell의 네이티브 표준출력으로 전달할 때 한글 설명이 손상되어 생성 타입의 재현성 검사가 흔들렸다.
- 원인: Windows PowerShell의 네이티브 프로세스 표준출력 인코딩과 UTF-8 JSON 간 불일치.
- 조치: Python이 임시 OpenAPI JSON 파일을 UTF-8로 직접 기록하고, PowerShell이 해당 파일을 UTF-8로 읽도록 `scripts\generate-openapi-types.ps1`을 수정했다.
- 결과: 생성과 `-Check`를 연속 실행해 `OPENAPI_TYPES_UP_TO_DATE` 확인.

### OFFICE-ENV-003 — W1B 실DB 하네스 종료 로그의 오류 마커 오탐

- 증상: W1B Playwright 3건, DB 사후검사, 누출 검사, 리스너·임시 폴더 정리는 모두 성공했지만 종료된 백엔드 로그에서 하네스 오류 마커가 검출되어 최종 종료 코드가 1이 되었다.
- 원인: W1B 하네스가 DB를 W1B 리비전 `20260730_0009_w1b_recipient`에 고정한 상태에서 최신 수급자 화면이 W1C 조회 API도 호출했고, 아직 존재하지 않는 W1C 테이블 접근이 `ProgrammingError` 로그를 남겼다.
- 조치: W1B 브라우저 시나리오에서 후속 웨이브인 W1C의 읽기 요청만 빈 상태로 격리했다. W1B API와 DB 요청은 계속 실제 PostgreSQL을 사용한다. 하네스에는 민감한 로그 본문을 노출하지 않고 검출 마커와 예외 유형만 출력하는 진단값을 추가했다.
- 결과: W1B Playwright 3건, 전후 DB 사후검사, 누출 검사, 리스너·Playwright 산출물·임시 클러스터 정리를 모두 통과해 `W1B_E2E_GREEN` 확인.

### OFFICE-ENV-006 — Git 작성자 identity 미설정

- 증상: 후보 커밋 시 Git이 `Author identity unknown`으로 커밋을 거부했다.
- 원인: 사무실 PC의 현재 저장소에 `user.name`과 `user.email` 설정이 없었다.
- 조치: 최근 저장소 커밋 8건에서 일관되게 확인된 작성자 `tryo528-blip <tryo528@gmail.com>`을 이 저장소의 local Git config에만 설정했다.
- 결과: global/system Git 작성자 설정과 집 환경에는 영향을 주지 않고 후보 커밋을 재시도할 수 있다.

### OFFICE-ENV-007 — PowerShell 실행정책이 Claude CLI 스크립트 shim 차단

- 증상: `claude` 명령이 `C:\Users\sswce\AppData\Roaming\npm\claude.ps1`을 선택한 뒤 PowerShell 실행정책 오류로 시작되지 않았다.
- 원인: 사무실 PC의 PowerShell 실행정책이 npm이 만든 `.ps1` shim 실행을 허용하지 않는다.
- 조치: 전역·사용자 실행정책은 변경하지 않고 같은 설치의 `claude.cmd` shim을 명시적으로 사용했다.
- 결과: `claude.cmd --version`에서 Claude Code `2.1.215`를 확인했고, Opus 독립감사를 정상 실행했다. 집 환경 기록과 설정에는 영향이 없다.

### OFFICE-ENV-009 — PowerShell 실행정책이 npm 스크립트 shim 차단

- 증상: PowerShell에서 `npm`을 호출하면 `C:\Program Files\nodejs\npm.ps1`이 선택되어 실행정책 오류로 프런트엔드 검증이 시작되지 않았다.
- 원인: 사무실 PC의 PowerShell 실행정책이 Node.js 설치가 제공한 `.ps1` shim 실행을 허용하지 않는다.
- 조치: 전역·사용자 실행정책은 변경하지 않고 `C:\Program Files\nodejs\npm.cmd`를 명시적으로 사용한다.
- 결과: 집 환경과 사무실 정책을 바꾸지 않고 동일한 npm 설치로 검증을 재실행할 수 있다.

### OFFICE-ENV-010 — 동시 감사 부하에서 Vitest 비동기 테스트 제한시간 초과

- 증상: 전체 프런트 단위 테스트를 기본 병렬 worker로 실행하면 기존 비동기 화면 테스트 2~3건이 DOM/API 대기 중 기본 제한시간을 넘겼다. 같은 파일을 단독 실행하면 모두 통과했다.
- 원인: Opus·요셉·마르코 감사와 PostgreSQL·브라우저 gate가 겹친 사무실 PC에서 여러 jsdom worker가 동시에 transform·import를 수행해 비동기 렌더 완료가 늦어졌다.
- 조치: 공식 `npm test` script에 `--maxWorkers=1`을 고정해 파일 실행을 직렬화했다. 개별 assertion이나 제품 대기시간은 완화하지 않았다.
- 결과: 공식 전체 명령이 16 files / 98 tests를 안정적으로 실행하며, W1C 집중·Playwright 병렬도와는 독립적으로 유지된다.

## 후속 처리

### OFFICE-ENV-004 — 프런트엔드 의존성 보안 경고

- 증상: `npm audit` 기준 high 등급 경고 4건.
- 현재 판단: W1C 기능 변경과 직접 관련 없는 기존 의존성 경고이며 자동 수정은 잠금 파일과 런타임 호환성을 바꿀 수 있다.
- 다음 조치: 취약 패키지와 의존 경로를 별도 확인하고, 테스트 가능한 의존성 갱신 작업으로 처리한다. `npm audit fix --force`는 사용하지 않는다.

### OFFICE-ENV-005 — Git LF→CRLF 변환 경고

- 증상: `git diff --check`와 상태 확인 때 수정 파일에 대해 LF가 다음 Git 처리 시 CRLF로 바뀐다는 경고가 반복된다.
- 확인값: 사무실 Git의 system 설정 `core.autocrlf=true`, 저장소 `.gitattributes` 없음.
- 현재 영향: `git diff --check` 오류는 0이며 의미 변경이나 공백 오류는 확인되지 않았다.
- 다음 조치: 집 환경의 Git 줄바꿈 설정과 비교한 뒤 저장소 단위 `.gitattributes` 도입 여부를 별도 결정한다. 사무실 PC의 system/global Git 설정은 이 작업에서 임의 변경하지 않는다.

### OFFICE-ENV-008 — Ruff 로컬 캐시 파일 갱신 접근 거부

- 증상: Ruff 검사 결과는 통과했지만 `backend\.ruff_cache\0.16.0\17465199987789727486` 캐시 파일 기록에서 Windows `Access is denied (os error 5)` 경고가 발생했다.
- 확인값: 파일과 상위 디렉터리 소유자는 현재 사무실 계정이며 ACL에도 수정 권한이 표시되어, 정적 ACL만으로는 원인이 확정되지 않았다.
- 현재 영향: `ruff --no-cache`로 동일 검사를 정상 통과했으며 소스 검사 결과에는 영향이 없다.
- 다음 조치: 작업 종료 후 관련 프로세스·보안 소프트웨어의 파일 잠금 여부를 확인하고, 안전한 로컬 캐시 경로임을 다시 확인한 뒤 캐시를 재생성한다. 집 환경 기록과는 별도로 유지한다.

### OFFICE-ENV-011 — 마르코 read-only 작업방의 PostgreSQL restricted-token startup 실패

- 전역 ledger 연관: `ENV-016`
- 증상: 최종 후보 `a86567f...` 독립 재검토에서 새 W1C PostgreSQL 하네스가
  Windows restricted-token startup preflight에서 exit `1`로 중단됐다.
- 제품 경계: 제품 assertion 실행 전 환경 실패이며 listener·임시 cluster·artifact
  잔여는 모두 `0`이었다.
- 검수 처리: 기술 재감사 SHA부터 최종 후보까지 runtime 대상 blob이 동일함을
  확인하고 기존 exact 실DB 증거를 재사용했다. 새 실DB 성공으로 기록하지 않았다.

### OFFICE-ENV-012 — 마르코 read-only 작업방의 `.vite-temp` 생성 거부

- 전역 ledger 연관: `ENV-016`
- 증상: focused frontend 재실행이
  `frontend\node_modules\.vite-temp` 생성 권한 거부로 시작되지 않았다.
- 제품 경계: test assertion 실패가 아니며 검수 종료 시 해당 경로는 존재하지 않았다.
- 검수 처리: W1C frontend·Playwright blob이 기존 exact runtime 검증 후보와
  동일함을 확인해 기존 증거를 재사용했다. 이 실행은 frontend PASS 수치에 더하지
  않았다.
