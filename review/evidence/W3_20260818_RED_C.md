첫 parser 구현 뒤 두 중간 실패도 문제 ledger에 보존한다.

- XML security preflight에서 `bytes.casefold()`를 호출해 정상/악성 입력 모두 같은
  `AttributeError`로 멈췄다. `bytes.lower()`로 교정했다.
- workbook dimension은 1000행이지만 실제 데이터 뒤 빈 스타일 행이 `EmptyCell`로
  반환되어 좌표 조회가 실패했다. iterator ordinal을 물리 행번호로 사용하고 완전 빈
  꼬리행만 제외하도록 교정했다.
- 두 차례 모두 DB/business write는 없었다.
- 최초 stable-mapping matcher는 후보의 외부키가 원본행 외부키와 정확히 같은지 내부에서
  다시 결합하지 않았다. source stable key를 request에 명시하고 없음·불일치·다건을 모두
  `REVIEW_PENDING`으로 닫는 RED를 추가한 뒤 교정했다.
- active content를 경로명으로만 차단하면 임의 확장자에 VBA content type/relationship을
  선언하는 우회가 가능했다. OOXML content-type과 relationship type 선언까지 검사하는
  RED를 추가했고 두 위장 입력을 모두 `ACTIVE_CONTENT_BLOCKED`로 닫았다.
- 보강 직후 external-link 입력도 더 일반적인 active-content 코드로 먼저 분류돼 기존
  오류 계약 1건이 실패했다. 외부 TargetMode 우선순위를 복원해
  `EXTERNAL_RELATIONSHIP_BLOCKED` 계약과 강화된 차단을 함께 유지했다.
- 전체 pytest 첫 실행은 호스트 `TEMP/TMP`의 Windows 경로 때문에 캡처 임시파일 정리에서
  종료됐다. 제품 실패가 아니며 `TEMP/TMP/TMPDIR=/tmp`로 고정한 재실행을 사용했다.
- 과거 DEBT manifest 검증기가 후속 dirty tree와 최신 HEAD를 과거 후보로 오인해 정상
  개발을 막는 RED를 재현했다. manifest bytes는 바꾸지 않고 이미 push된
  `b79939aa2e951ed66028c395f911c18047bbc3f3` Git tree를 검증하도록 교정했다.
- 모바일 보고서 첫 390px 렌더에서 SHA와 긴 branch/base 문자열 때문에 489px, 443px
  가로 overflow가 순서대로 발견됐다. digest와 meta에 강제 줄바꿈을 적용한 최종 렌더는
  `scrollWidth=clientWidth=390`이다. 재렌더 1회는 저장소 루트에서 실행해 Playwright
  package를 찾지 못했고 frontend 작업 디렉터리로 교정했다.
