## Included contract

`care_assignment` is a `PERIOD_FACT` whose active period must be fully inside
the selected `recipient_contract` period and the selected
`staff_employment` period. It must also be fully covered by active
`staff_position_period` rows for the same `staff_id`+`employment_id` with
`position_code='CARE_WORKER'`. `GENERAL` assignments use the selected contract's
`service_type_id`; the same staff's active
`staff_service_qualification_period` facts must cover every assignment day.
The qualification test is coverage of the whole assignment range, not a
syntax-only, license-only, or single-day existence check. Position coverage and
service-qualification coverage are separate W1E eligibility guards; both use
`CARE_ASSIGNMENT_STAFF_INELIGIBLE` for the matrix-proposed eligibility failure.

The table contract is:

- `id` is a stable bigint `GENERATED BY DEFAULT AS IDENTITY` fact ID.
- `recipient_contract_id` is a required RESTRICT FK.
- `(staff_id, employment_id)` is a required composite RESTRICT FK to
  `staff_employment(staff_id, id)`; the replacement self-FK is
  `replacement_assignment_id -> care_assignment(id)` with RESTRICT and
  initially deferred behavior.
- `assignment_kind` is `GENERAL` or `FAMILY`; this packet exercises only the
  GENERAL path. `family_relationship_text` is retained for the excluded
  FAMILY slice and is not given W1E-A1 behavior.
- `start_date` is required; `end_date` is nullable; the generated
  stored `assignment_period` is exactly
  `daterange(start_date, end_date + 1, '[)')` and is required.
- Active rows carry the common invalidation/replacement/audit/`row_version`
  fields. Active same-contract+same-staff periods are excluded from overlap;
  a different staff member may have a simultaneous active GENERAL assignment.
- The catalog/ORM gate requires the exact 16-column table contract and rejects
  undeclared extra columns, with material types and nullability matching this
  list.

Forward guards are deferred and validate contract containment, employment
containment, CARE_WORKER position coverage, and GENERAL service-qualification
coverage. Reverse/orphan guards reject contract, employment, position, and
qualification truncation/invalidation/replacement when an active assignment
would be left outside its relied-upon fact. The existing
`fn_staff_employment_child_periods_reverse_guard` is extended to include
`care_assignment`; W1E also owns contract, position, and qualification reverse
guards. Parent and child correction in one transaction remains allowed when the
final state is covered.

## PERIOD_FACT correction

An assignment correction never silently edits the historical fact or treats
`row_version` as a business revision ID. The old row is invalidated, a new
fact row is inserted with `replacement_assignment_id = NULL`, and then the
old row's `replacement_assignment_id` is set to the new row's ID. Both stable
IDs remain distinct; active-only exclusion and guards ignore the invalidated
row, and historical references continue to resolve to the old fact ID.

order-independent. W1A already prevents CARE_WORKER-position and
qualification child periods from extending beyond employment, so an assignment
outside employment also loses those child coverages. The catalog check seals
the complete executable `prosrc` path: one active-assignment

lookup, the active-employment filter, the `assignment_period <@
employment_period` direction, and the immediately bound `23514` raise/return
